Embed an island from a remote app in a Next.js App Router page. This guide covers the host only. To build the remote, see [Writing an island remote](writing-an-island-remote.md).

<Callout>
  **Good to know:** Supported: Next.js 16 or 15 (`>=15.5.28 <17`), React 19, Turbopack or webpack,
  Node 20.9 or newer. `cacheComponents` needs Next 16 ([Limits](limits.md#nextjs-15)). A remote can
  also ship [remote components](remote-components.md) instead of islands, and a host can use both.
  [Islands or remote components?](remote-components.md#islands-or-remote-components) compares them.
</Callout>

## Add an island to a page

<Steps>
<Step>

### Install the packages

```npm
npm install @next-federation/core @next-federation/next @next-federation/react server-only
npm install --save-exact react@19.3.1 react-dom@19.3.1
```

Pin React to one exact version, the one the repo's tests run (19.3.1), whatever version
`create-next-app` scaffolds. Check `package.json`: `--save-exact` does not remove a caret that is
already there.

</Step>
<Step>

### Wrap your Next config

The wrapper is required. Adapter entry points fail with [`NF-017`](../errors/next-config-wrapper-missing.md) without it.

```ts title="next.config.ts"
import { withNextFederation } from '@next-federation/next/config'

export default withNextFederation({
  // your Next config, e.g. cacheComponents: true
})
```

The wrapper records whether `cacheComponents` is on, so the adapter picks the matching cache
implementation ([Caching](caching.md)).

</Step>
<Step>

### Define the federation

Use two files. The first is the config and imports nothing from Next.js, so `nf-types` can load it
with plain Node.

```ts title="lib/federation.config.ts"
import { defineFederation } from '@next-federation/core'

export const federation = defineFederation({
  remotes: {
    shop: { origin: process.env.SHOP_ORIGIN ?? 'https://shop.example.com' },
  },
})
```

The second creates the island components.

```ts title="lib/federation.ts"
import 'server-only'
import { createIslands } from '@next-federation/next/server'
import { federation } from './federation.config'

export { federation }
export const { RemoteIsland, preloadIsland, revalidateIsland } =
  createIslands(federation)
```

A remote is an origin, not a path. The host fetches envelopes only from this origin (and from
`assetOrigins`, if you list any), and it refuses redirects.

</Step>
<Step>

### Render the island

```tsx title="app/page.tsx"
import { RemoteIsland } from '../lib/federation'

export default function Home() {
  return (
    <main>
      <RemoteIsland
        remote="shop"
        island="ProductPanel"
        props={{ sku: 'A1' }}
        fallback={<p>loading product…</p>}
        errorFallback={<p>product unavailable</p>}
      />
    </main>
  )
}
```

`props` must be plain JSON: functions, `Date`, `Map` and class instances throw [`NF-009`](../errors/props-not-json.md).
`errorFallback` shows when the remote is down, slow or returns an invalid envelope, and the page
still answers `200`.

</Step>
<Step>

### Open the CSP

Add each remote origin to `script-src`, `connect-src` and `style-src`. Next.js needs more than that
to run under a CSP at all: [CSP](csp.md) has a complete policy for dev and production.

</Step>
</Steps>

<Callout>
  **Good to know:** Public islands are cached. `revalidate` (seconds) on
  `RemoteIsland` overrides `islands.revalidate`, and `dynamic` fetches on every
  request ([Caching](caching.md)).
</Callout>

## Show per-user content

A private island renders for the signed-in user. Add `identity` to `defineFederation`, a
`getIdentity` function and the token routes ([Identity](identity.md) has the full setup), then mark
the island `private`.

```tsx title="app/orders/page.tsx"
<RemoteIsland
  remote="shop"
  island="MyOrders"
  private
  fallback={<p>loading orders…</p>}
  errorFallback={<p>sign in to see your orders</p>}
/>
```

Always give a private island an `errorFallback`. A visitor who is not signed in makes no request and
sees it: without one, they see the loading text for good.

## Put private content in the first HTML

By default a private island streams: the first HTML holds `fallback`, and the island's HTML follows
in the same response. Add `blocking` to render it in the first HTML instead, for clients without
JavaScript, crawlers or layouts that must not shift.

```tsx title="app/orders/page.tsx"
// With cacheComponents only: Next refuses `instant` without it.
export const instant = false
```

<Callout type="warn">
  **Good to know:** `blocking` makes the whole route per-request and adds the
  remote's response time to the page's first byte.
  [Caching](caching.md#blocking-the-island-in-the-first-html) lists the costs,
  the Next config each host needs and what happens when `getIdentity` throws.
</Callout>

## Tune timeouts and retries

Each island fetch has a total budget of `timeoutMs` (default `3000`) and retries a network error or a
`502`, `503` or `504` once. Set both for all remotes or per remote:

```ts title="lib/federation.config.ts"
export const federation = defineFederation({
  islands: { timeoutMs: 5000, retries: 2 },
  remotes: {
    shop: { origin: 'https://shop.example.com' },
    reports: {
      origin: 'https://reports.example.com',
      timeoutMs: 8000,
      retries: 0,
    },
  },
})
```

[Timeouts and retries](limits.md#timeouts-and-retries) lists what is and is not retried.
