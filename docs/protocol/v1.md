# Island protocol v1

This is the wire contract between a **host** (an app that embeds islands) and a **remote** (a server
that renders them). It is bundler-neutral: any server that implements it works with any host. The
reference codec is [`@next-federation/protocol`](../../packages/protocol).

## Versioning

The protocol version is an integer major, carried as `protocolVersion` in every envelope. Adding
fields is compatible: a host keeps and ignores fields it does not know. Any change that removes or
reinterprets a field bumps the major. A host that receives an unknown major renders its fallback and
reports `NF-003`.

## Island request

Endpoint: `<base>/_nf/island/<island>`, where `<island>` matches `^[A-Za-z][A-Za-z0-9_-]*$` and `<base>`
is the remote's absolute URL, optionally build-pinned (`https://r.example/b/<buildId>`). A server
takes the island name from the path segment after the **last** `/_nf/island/`.

- `GET <url>?p=<props>&h=<host>`: `p` is base64url (no padding) of the canonical JSON of the props;
  `h` is the same for the host context `{ "basePath": string, "locale": string }`. `h` is omitted when
  the host context is `{ "basePath": "", "locale": "" }`. `locale` is the URL prefix segment, `""` for
  none or the default locale.
- When `p` would be longer than 2048 characters the host sends `POST <url>` with
  `content-type: application/json` and the body `{ "props": ..., "host": ... }`, and no `p` or `h` in
  the URL.
- Canonical JSON has object keys sorted and no spaces or newlines, so equal props produce equal URLs
  (cacheable). Props must be plain JSON: functions, symbols, bigints, `NaN`/`Infinity`, `Date`,
  `Map`/`Set`, class instances and cycles are rejected (`NF-009`). Object properties whose value is
  `undefined` are dropped.
- `null` or `undefined` props are encoded as `{}`. A server decodes a missing or empty `p` as `{}`
  props and a missing or empty `h` as `{ "basePath": "", "locale": "" }`.
- Headers: `accept: application/json`. `Authorization: Bearer <jwt>` only when the host has a token.
  Requests never carry cookies (`credentials: 'omit'`).

## Response envelope

A successful response is `200` with a JSON body:

| Field | Type | Meaning |
|---|---|---|
| `protocolVersion` | `1` | Checked first. Anything else is `NF-003`. |
| `remote` | string | The remote's own name. |
| `buildId` | string | Build that rendered this envelope. |
| `mode` | `"development"` or `"production"` | React mode of the rendering server. The client bundle must match (`NF-006`). |
| `html` | string | Server-rendered markup of the island. No `<script>` or `<link>` tags. |
| `rscPayload` | string | The island's Flight payload, for hydration. |
| `css` | string[] | Absolute stylesheet URLs. |
| `bootstrap` | string | Absolute URL of an ES module implementing the bootstrap contract below. |
| `reactVersion` | string | React version of the remote's client bundle. |
| `idPlaceholder` | string | Token present in `html` and `rscPayload`, matching `^[A-Za-z0-9_-]{4,}$` (non-empty; anything else is `NF-004`). The host replaces every occurrence with a per-mount prefix so one envelope can be mounted many times. |

Any missing or mistyped field, non-absolute `bootstrap` or `css` URL, or `mode` outside the union is
`NF-004`. A host checks that `bootstrap` and every `css` URL are on origins it allows for that
remote and are `http(s)`, otherwise `NF-005`.

```json
{
  "protocolVersion": 1,
  "remote": "shop",
  "buildId": "v1",
  "mode": "production",
  "html": "<section id=\"nfid-1a2b3c4d-R1\"><h2>Widget</h2></section>",
  "rscPayload": "0:[\"$\",\"section\",null,{\"id\":\"nfid-1a2b3c4d-R1\"}]\n",
  "css": ["https://shop.example/b/v1/assets/panel-3f9a.css"],
  "bootstrap": "https://shop.example/b/v1/assets/bootstrap-81c2.js",
  "reactVersion": "19.3.1",
  "idPlaceholder": "nfid-1a2b3c4d-"
}
```

### Per-mount identity

To mount, the host replaces `idPlaceholder` with `idPlaceholder + <mountId stripped to [A-Za-z0-9]> + "-"`
in `html` and `rscPayload`, and passes that same string as React's `identifierPrefix`. Two mounts of
one envelope therefore never share element ids.

## Status codes

Every response carries `Vary: Origin, Authorization`. Every response to an allowed `Origin` carries
the CORS headers, including errors. Error bodies are `{"error":"NF-0xx"}`, except the empty-bodied 404 and the 204.

**Precedence.** A server evaluates, in order: (1) `GET /_nf/health`, (2) `OPTIONS`, (3) the `Origin`
check, and only then the rows below, top to bottom. So health checks and preflights are answered
regardless of `Origin`.

| Condition | Status | Cache-Control |
|---|---|---|
| `GET /_nf/health` (any prefix) | 200 `ok` | no-store |
| `OPTIONS` | 204 | none |
| `Origin` present and not allowed | 403 `NF-022`, no CORS headers | no-store |
| path does not contain `/_nf/island/` | 404, empty body (no code) | no-store |
| method not GET/POST | 405 | no-store |
| body larger than the server's limit (`Content-Length` or bytes read; default 65536 bytes, server-configurable) | 413 | no-store |
| path contains `/_nf/island/` but the island name is empty or invalid, or props or host context are undecodable | 400 `NF-004` | no-store |
| well-formed island name the server does not expose | 404 `NF-021` | no-store |
| token malformed, expired, badly signed or with the wrong audience, or a private island requested with no token | 401 `NF-014` | no-store |
| token whose issuer is not in the remote's issuer map | 401 `NF-016` | no-store |
| signing keys unavailable | 503 `NF-015`, `Retry-After: 5` | no-store |
| render failed, or a css/bootstrap URL is not absolute | 500 | no-store |
| build retired or unknown (build-pinned path) | 410 `NF-023` | no-store |
| success, no token | 200 envelope | `public, max-age=<maxAge>` |
| success, token presented | 200 envelope | `private, no-store` |

## Caching headers

Public responses are `Cache-Control: public, max-age=60` by default. Any response to a request that
carried a token is `private, no-store`, so a shared cache never stores user-specific markup.

## Bootstrap module contract

`bootstrap` is an ES module with one named export:

```ts
type IslandBootstrapModule = {
  mountIsland(container: HTMLElement, options: MountIslandOptions): IslandHandle
}
type MountIslandOptions = {
  envelope: { remote: string; buildId: string; mode: 'development' | 'production' }
  rscPayload: string        // already prefixed by the host
  identifierPrefix: string  // already computed by the host
  bridge: { navigate(href: string): void; prefetch(href: string): void; basePath: string; locale: string }
  getToken?: () => Promise<string | null>
  onError?: (error: unknown, kind: 'uncaught' | 'caught' | 'recoverable') => void
}
type IslandHandle = { update(next: { rscPayload: string }): void; destroy(): void }
```

The container already holds the server HTML; `mountIsland` hydrates it. `destroy` releases everything
the mount created. **A bootstrap must be safe next to other remotes' bootstraps, and other builds of
the same remote, on one page**: it keeps no state in shared globals except under a name that includes
its remote and build, and it never assumes it is the only React on the page.

## Build pinning

Every URL in an envelope is absolute and build-pinned (`<base>/b/<buildId>/assets/...`), so an
envelope cached by a host keeps working for as long as that build is served. A build the remote has
retired answers `410 NF-023`; the host then shows its fallback and refetches.

## Identity

When a host sends a token it is a JWT in `Authorization: Bearer`, signed with ES256, with `aud` equal
to the remote's name. The host publishes its keys as a JWKS. The token is never placed in the URL or
body.

## Reserved

`/_nf/action` and the `X-NF-Action` request header are reserved for server actions (a later phase).
Servers must not use them for anything else; `X-NF-Action` is already in the CORS allow-headers.

## Writing a remote without Vite

Serve `GET /_nf/health`, and `GET`/`POST /_nf/island/<name>` following the tables above. Render the
island to HTML and a Flight payload with any bundler, put a unique `idPlaceholder` in both, build a
browser module that exports `mountIsland`, and emit absolute build-pinned URLs for it and for the
stylesheets. `@next-federation/protocol` gives you `decodeIslandRequest` for the request side and
`parseEnvelope` to check what you produce.
